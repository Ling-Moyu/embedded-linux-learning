## vim：三个模式

| 模式     | 进入方式            | 作用    |
| ------ | --------------- | ----- |
| 普通（默认） | `Esc`           | 按键是命令 |
| 插入     | `i` / `a` / `o` | 打字    |
| 命令行    | `:`             | 保存、退出 |

- 常用键：`i` 插入、`Esc` 回普通、`:wq` 保存退出、`:q!` 不保存强退、`dd` 删行、`yy` 复制行、`p` 粘贴、`u` 撤销、`/词` 搜索（`n` 下一个）、`gg` 首行、`G` 末行、`3dd` 删三行
- 核心模型：**编辑的是内存缓冲区，`:w` 才写入磁盘**，所以 `:q!` 后磁盘文件一点不变（第一次见到还挺惊讶）

## gcc 与编译运行

```bash
gcc hello01.c -o hello01 && ./hello01
```

- `gcc` = 编译器，把 .c 翻译成可执行文件
- `-o` = output，指定成品名字（不写就默认 a.out）
- `&&` = 前面成功才执行后面（编译失败就不去跑旧程序）
- `./xxx.c` 是错的：.c 是给人看的源码，不是程序，bash 会当成脚本解释 → `syntax error near unexpected token '('`

## C：一个真 bug 和一个新概念

- bug：`int max = arg[0];` 写在 for 循环体内 → 每轮都被重新初始化，上一轮的最大值被冲掉，结果输出 6 而不是 8。修法：把 max 声明挪到循环外
- 下标：数组编号从 0 开始，5 个元素下标只到 4，写 arg[5] 就是越界（C 不检查）
- 扩展题：`max=8 index=3`，在 `arg[i] > max` 成立那一刻把 `i` 记下来

## find 与管道

```bash
find /usr/include -name "*.h" -type f | xargs grep -l "printf"
find /usr/include -name "*.h" -type f -exec grep -l "printf" {} \;
```

- `-name` 按名字、`-size +1M` 按大小、`-type f` 只要文件（排除目录，实战必带）
- `-exec ... \;` ：对每个找到的文件执行一次，`{}` 是文件名占位符
- `xargs`：把上游的一堆路径拼成下游命令的参数  
  |  |  |  
  | --- | --- |
- `| head`：只看前 10 行；下游提前退出会让上游收到 **signal 13 (SIGPIPE)**，属于正常现象
- 验证思路：结果为 0 时用 `-size +1k` 做对照组，确认命令本身没写错
