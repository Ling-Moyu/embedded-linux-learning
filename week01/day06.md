# Day 6 · gcc 深入 + Makefile

## 核心认知：编译是四步，不是一步

```
main.c ──预处理──> main.i ──编译──> main.s ──汇编──> main.o ──链接──> app
        (展开#include)     (生成汇编)    (生成机器码)   (多个.o拼在一起)
```

- 多个 .c 文件各自编译成 .o，最后链接成一个可执行文件
- `-c` = 只编译不链接，产出 .o（目标文件，是机器码但不能直接跑）

## 头文件三件事

- `#include "x.h"`：先在当前目录找（自己写的头文件用这个）
- `#include <stdio.h>`：只在系统目录找
- 头文件卫士：`#ifndef/#define/#endif` 防止头文件被 include 两次

## gcc 常用参数

| 参数      | 作用              | 备注                       |
| ------- | --------------- | ------------------------ |
| `-o 名字` | 指定输出文件名         | 不加默认 a.out；**注意别打成数字 0** |
| `-Wall` | 打开所有常用警告        | **永远带上**，警告里藏着真 bug      |
| `-g`    | 写入调试信息（行号/变量名表） | gdb 能看行号全靠它；发布版不带        |
| `-c`    | 只编译不链接          | 产出 .o                    |
| `-O2`   | 优化（发布时用）        | 调试期别和 -g 一起用，代码会对不上行号    |

## gdb 初体验：抓段错误

流程：`gcc -g xxx.c -o app` → `gdb ./app` → 在 `(gdb)` 提示符下敲命令

| 命令     | 作用                               |
| ------ | -------------------------------- |
| `run`  | 运行程序，崩溃时停在案发现场                   |
| `bt`   | backtrace，打印调用栈，直接看到 `main.c:行号` |
| `quit` | 退出 gdb                           |

- `(gdb)` 提示符 = 在 gdb 的地盘里；`$` = 在 bash 里。**看提示符知道自己在哪**
- gdb 是"程序里还有程序"的交互式程序（和 mysql、python 交互模式同一个套路）
- 这次越界访问内核报的是 **SIGBUS**（信号），和段错误 SIGSEGV 是一家人

## Makefile 核心

### 一条规则的结构

```makefile
目标: 依赖
	命令            ← 开头必须是 Tab，不能是空格（第一大坑）
```

### make 的核心规则（时间戳）

> **目标比依赖旧 → 重新执行命令；目标比所有依赖都新 → 什么都不做（up to date）**

- 依据是文件修改时间戳
- `touch 文件` = 只刷新时间戳，不改内容
- 意义：大工程只重编改过的文件，编译时间从 5 分钟变 3 秒

### 模板规则 + 自动变量（工程级写法）

```makefile
CC = gcc
CFLAGS = -Wall -g
TARGET = app
OBJS = main.o calc.o

$(TARGET): $(OBJS)
	$(CC) $^ -o $@

%.o: %.c calc.h
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) $(TARGET)

.PHONY: clean
```

| 写法                | 含义                                            |
| ----------------- | --------------------------------------------- |
| `CC = gcc`        | 变量定义（**Makefile 里等号两边空格随意**，这和 bash 是两套语法）    |
| `$(CC)`           | 使用变量                                          |
| `%.o: %.c calc.h` | 模板规则：任何 .o 由同名 .c + calc.h 生成，加文件不用改 Makefile |
| `$@`              | 本次的目标名                                        |
| `$^`              | 本次的所有依赖                                       |
| `$<`              | 本次的第一个依赖                                      |
| `.PHONY: clean`   | 声明 clean 是假目标，防止和同名文件冲突                       |

- 头文件必须写进依赖：不写的话，改了 .h make 根本不理（实验验证过）
- `make clean` 会先执行删除再重编

## 今天踩的两个坑（都很有价值）

1. **`CFALGS = -Wall -g` 打错了变量名** → make 对未定义变量**静默置空**（和 bash 的 fate 事故同一机制），编译时 `-Wall -g` 全没了，唯一线索是输出命令里多了个双空格
   - 教训：make 执行前会 echo 展开后的命令，**这个 echo 就是对账单，跑完看一眼**
2. **`touch calc.h` 后 make 说 up to date** → 因为规则里没写 calc.h，make 不知道它的存在
   - 教训：make 只认规则里写了的依赖

## 其他收获

- 发布版用 `-O2`，调试版用 `-O0 -g`；`strip` 命令可剥掉调试信息减小体积
- `:set paste` 再粘贴，防止 vim 自动缩进搞乱格式；`:set list` 让 Tab 显示成 `^I` 便于检查
