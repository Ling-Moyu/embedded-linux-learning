## 脚本三要素

1. 第一行 `#!/bin/bash`（shebang）：告诉内核"用 bash 执行我"——执行 ./xx.sh 时内核实际转成 /bin/bash xx.sh；`#!` 后面跟谁文件就被谁解释（实验过 #!/bin/rm 会把自己删掉）
2. 命令清单：从上到下逐行执行
3. 可执行权限：`chmod 755 xx.sh` 或 `chmod +x`（文件没有 x 位 → Permission denied）

## 特殊变量

| 变量           | 含义                                  |
| ------------ | ----------------------------------- |
| `$1` `$2`... | 第1、2个参数                             |
| `$#`         | 参数个数                                |
| `$0`         | 脚本自己的名字                             |
| `$?`         | 上一条命令的退出码（0=成功，非0=失败）               |
| `$()`        | 执行命令并把输出结果塞回来，如 `today=$(date +%F)` |

## `[ ]` 判断：它是一条命令（test），不是语法符号

- 数字比较用字母缩写：`-eq` 等 / `-ne` 不等 / `-gt -lt -ge -le`
- 字符串比较用 `=` 和 `!=`
- 文件判断：`-f 文件`（是普通文件）、`-d 目录`（是目录）
- 取反：`[ ! -d "$src" ]` = 目录不存在
- **内侧必须有空格**：`[ $# -eq 0 ]`，没空格拼不成命令

## if / exit / set -u

- `if ...; then ... else ... fi`，fi 是 if 倒着写
- `exit 1`：以失败状态退出，是一道闸门——条件不对别往下走（rxit 事故：exit 打错，脚本继续跑，错误参数往下执行）
- `set -u`：用了未定义变量立刻报错退出（unbound variable），防止 bash 默认的"静默空值"（fate 事故：today 变量名打错，生成 backup\_.tar.gz，一点错都不报）
- 老手写法：`set -eu`

## tar：打包箱

- 本职是打包（装箱），压缩靠 gzip（`-z` 顺手叫它）
- 三个互斥动作：`c` 建包 / `x` 解包 / `t` 看包内容
- `z` = 调 gzip，`f` = 后面紧跟包名，`v` = 显示过程
- `C`（大写）= 先切到指定目录再操作：打包时让包内路径干净（消除 Removing leading '/' 警告），解包时解到指定目录
- 实验：pack.tar 10K → pack.tar.gz 147 字节，文本压缩率惊人；图片视频等已压缩内容 gzip 挤不出多少

## 踩坑记录

1. `fate=$(date +%F)`：变量名 typo → bash 把它当命令 → "command not found"，且 `${today}` 静默变空 → 日期丢失。教训：bash 对不存在的变量一声不吭
2. `rxit`：exit 打错 → 闸门失效，脚本带病继续跑
3. `if tar -czf ...; then` 的 `...` 原样照抄 → tar 报 "Cowardly refusing to create an empty archive"（胆怯地拒绝空包）。教训：省略号是提示语，不是代码
4. 改代码"追加"而不是"替换" → 新旧逻辑都执行
5. tar 的 `-C`（切目录）写成 `-c`（建包）→ "You may not specify more than one '-Acdtrux'"。大小写是两个字符，gcc 的 -o/0、tar 的 C/c，都是同一类坑
6. `~` 和 `./` 的区别再次实战：备份写到 `~/`，却在 `./` 下找，当然找不到

## 最终成品：backup.sh（挑战版）

- 两个参数：源目录 + 备份存放目录
- `$# -ne 2` 校验参数、`-d` 校验目录存在、`mkdir -p` 自动建目录
- `if tar ...; then ... else ... fi` 检查执行结果，失败走 stderr（>&2）并 exit 1
- `-C "$HOME"` 让包内路径干净
- 变量一律加双引号 `"$src"`，防空格路径被拆
- 退出码验收：失败后 `echo $?` 输出 1
